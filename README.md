## Описание проекта

**LifterAI** — это интеллектуальная RAG-система (Retrieval-Augmented Generation) нового поколения для технической поддержки и диагностики лифтового оборудования. Система использует локальную или облачную языковую модель для генерации точных, структурированных ответов на основе внутренней технической документации и актуальных данных из интернета.

### Ключевые возможности

- 🧠 **Умное извлечение сущностей (NER)**: ИИ самостоятельно определяет станцию, код ошибки и симптомы из естественного текста пользователя. Никаких выпадающих списков.
- 🌐 **Изолированный веб-поиск**: Интеграция с Tavily/SerpAPI через защищенный VPN-прокси (Xray) для поиска актуальных мануалов и решений, которых нет в локальной базе.
- 📚 **Гибридный RAG**: Одновременный семантический поиск по локальной векторной базе (Qdrant) и в интернете.
- 💬 **Упрощенный UI**: Современный чат-интерфейс, похожий на ChatGPT, с отображением источников информации.
- 🔌 **Готовность к CRM**: Асинхронный Webhook-роутинг для двусторонней интеграции с внешними CRM-системами.
- 🔒 **Безопасность**: Веб-поиск изолирован в отдельном контейнере, основной трафик сервера не затрагивается.

## Технологический стек

### Backend
- **Node.js 20+** & **TypeScript** — типизированная среда выполнения
- **Express 5** — веб-фреймворк
- **LangChain** — оркестрация LLM и RAG-пайплайнов
- **Undici** — продвинутый HTTP-клиент с поддержкой проксирования

### AI & Data
- **Ollama** — локальный хостинг моделей (рекомендуется `qwen2.5:7b` или `qwen2.5:3b`)
- **Qdrant** — векторная база данных для семантического поиска
- **Tavily API** (или SerpAPI) — поисковый движок, оптимизированный для ИИ

### Инфраструктура
- **Docker & Docker Compose** — контейнеризация
- **Xray-core** — изолированный прокси-сервер для безопасного доступа к внешним API

### Frontend
- **Vanilla JS / HTML5 / CSS3** — легковесный, быстрый интерфейс без тяжелых фреймворков
- **Marked.js** — рендеринг Markdown-ответов от ИИ

## Установка и развертывание

### Шаг 1: настройка окружения

```bash
 
# Создайте файл .env
cat << 'EOF' > .env
PORT=3001
NODE_ENV=development
OLLAMA_BASE_URL=http://ollama:11434
OLLAMA_MODEL=qwen2.5:7b
QDRANT_URL=http://qdrant:6333
TAVILY_API_KEY=tvly-ваш_ключ_от_tavily
EOF
```

### Шаг 2: Запуск инфраструктуры

```bash
# Запуск всех сервисов (Backend, Frontend, Qdrant, Ollama, Xray-proxy)
docker compose up -d

# Проверка статуса
docker ps
```

### Шаг 3: Загрузка AI-моделей

```bash
# Загрузка основной модели (рекомендуется 7b для сложных промптов)
docker exec ollama ollama pull qwen2.5:7b

# Загрузка модели эмбеддингов
docker exec ollama ollama pull nomic-embed-text
```

### Шаг 4: Инжестинг базы знаний

```bash
# Загрузка документов из папки knowledge/ в Qdrant (с безопасным батчингом)
docker exec lifterai-backend npm run ingest
```

## Конфигурация

### Критически важные настройки

1. **`src/config/ollama.ts`**: Убедитесь, что `baseUrl` указывает на имя контейнера, а не на localhost:
   ```typescript
   export const OLLAMA_CONFIG = {
       baseUrl: process.env.OLLAMA_BASE_URL || "http://ollama:11434",
       chatModel: process.env.OLLAMA_MODEL || "qwen2.5:7b",
       embeddingModel: "nomic-embed-text"
   };
   ```
2. **`xray-config.json`**: В секции `inbounds` порты `10808` и `10809` должны слушать `"0.0.0.0"`, чтобы быть доступными для других контейнеров Docker.

## Использование

### Веб-интерфейс

1. Откройте браузер: `http://localhost:8080` (или IP вашего сервера).
2. **Просто напишите свой вопрос естественным языком.** Не нужно выбирать контроллеры из списков!
   - *Пример 1:* `"шулм как посмотреть историю ошибок"`
   - *Пример 2:* `"nice3000 ошибка 41, кабина не едет"`
3. ИИ автоматически определит станцию и код ошибки, найдет информацию в Qdrant и через VPN в интернете, и выдаст структурированный ответ со ссылками на источники.

### API Endpoints

#### `POST /api/chat` (Для веб-фронтенда, синхронный)
```bash
curl -X POST http://localhost:3001/api/chat \
  -H "Content-Type: application/json" \
  -d '{
    "chat_id": "session-123",
    "user_id": "web_user",
    "message": "nice3000 ошибка 41"
  }'
```
**Ответ:**
```json
{
  "answer": "**Ошибка 41:** Разрыв цепи безопасности...\n\n**Действия:**\n1. Проверьте...",
  "sources": [
    { "title": "Monarch NICE3000 Error Codes", "url": "https://..." }
  ]
}
```

#### `POST /api/webhooks/crm` (Для внешней CRM, асинхронный)
Принимает запрос, мгновенно возвращает `200 OK`, обрабатывает ИИ в фоне и отправляет результат через настроенный сервис отправки (например, `mock-crm.service.ts`, который позже заменяется на реальный API CRM).

## Решение проблем

### 1. Ошибка: `ECONNREFUSED 127.0.0.1:11434`
**Причина:** Код пытается обратиться к Ollama как к localhost внутри контейнера.  
**Решение:** Проверьте `src/config/ollama.ts` и `.env`. `baseUrl` должен быть строго `"http://ollama:11434"`. Перезапустите: `docker compose up -d --force-recreate --no-deps backend`.

### 2. Ошибка: `fetch failed` при `npm run ingest`
**Причина:** Qdrant не выдерживает нагрузку при попытке загрузить все чанки одним запросом.  
**Решение:** Убедитесь, что в `src/ingest.ts` реализован цикл с батчингом (загрузка по 50-100 документов за раз с небольшой задержкой `setTimeout`).

### 3. ИИ выдает "Ошибка null" или выдумывает действия
**Причина:** Модель (особенно 3B) путается в сложных промптах, когда код ошибки не указан, а пользователь спрашивает про процедуру.  
**Решение:** 
1. Используйте модель `qwen2.5:7b` (указано в `.env`).
2. Убедитесь, что в `chat.route.ts` и `webhook.route.ts` используется обновленный промпт с четким разделением на **Тип А (Диагностика)** и **Тип Б (Процедура)**.

### 4. Ошибка: `xray xray: unknown command`
**Причина:** В `docker-compose.yml` в команде запуска xray продублировано слово `xray`.  
**Решение:** Измените команду на `command: ["run", "-c", "/etc/xray/config.json"]`.

## Безопасность

- **Изоляция трафика:** Поиск в интернете (Tavily/SerpAPI) осуществляется исключительно через контейнер `xray-proxy`. Основной трафик сервера и локальная сеть не затрагиваются.
- **Внутренняя сеть Docker:** Сервисы `qdrant` и `ollama` не проброшены на хост-машину (нет секции `ports` в `docker-compose.yml` для них), доступ к ним имеет только `lifterai-backend`.
- **Защита от галлюцинаций:** Промпт жестко ограничивает ИИ рамками предоставленных источников (`[QDRANT]` и `[INTERNET]`), запрещая выдумывать параметры или смешивать инструкции от разных ошибок.
